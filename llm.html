LLM 对齐：RLHF、DPO、GRPO

把上一页的 PPO 接到语言模型上。状态是 prompt+已生成 token，动作是下一个 token，奖励往往整段回复才打一分。

生成就是 MDP

RL语言模型
s到目前为止的 token 序列（含 prompt）
a下一个 token，动作空间 = 词表
π(a|s)softmax(logits / T)
转移确定性：s' = concat(s, a)
奖励多数位置是 0；结束时给一个序列分数，或逐步给格式/正确性

序列对数概率是逐步加起来的：

log π(y | x) = Σ_t log π(y_t | x, y_<t)

训练几乎总是 teacher-forcing：用已经采样好的 y，逐步算每个 token 的 logπ，不再重新采样。采样（temperature / top-p）只发生在 rollout；算 logprob 时不要再乘一遍温度。

损失只落在 completion token 上。prompt、padding、图像占位、工具观察，都要 mask 掉。框架里这个张量叫 completion_mask / loss_mask。

为什么 SFT 不够

SFT 最大化 log π(y|x)，y 来自人类示范。它不会说「这个答案比那个好多少」，也不会在没有示范的题上自己探索。要对齐「更好」，需要能比较、能探索的目标：RL 或 RL 的近亲。

经典三阶段（InstructGPT / PPO-RLHF）

  1. SFT：示范数据，得到 π_SFT。
  2. Reward model：人类在 (y_w, y_l) 里选更好的，学 r_φ(x,y)。损失是 Bradley-Terry：−log σ(r_w − r_l)。
  3. PPO：策略最大化 r_φ，同时 KL 惩罚别离 SFT 太远。
r_t = 0 for t < T
r_T = r_φ(x,y) − β KL_t          # KL 可以逐步加，也可以只加在序列级
KL_t ≈ log π_θ(y_t|s_t) − log π_ref(y_t|s_t)

现场要四个模型：policy、SFT/ref、RM、value。Value 用 GAE 把稀疏的序列奖励变成逐步优势。工程重，所以后来有 DPO 和 GRPO。

KL 估计常用：

名字公式用途
k1logπ − logπ_ref无偏但方差大，当逐步惩罚
k3exp(logπ_ref − logπ) − (logπ_ref − logπ) − 1非负，监控用更稳

β 太大：模型不敢离 SFT，学不动奖励。β 太小：reward hacking，RM 被钻空子，语言崩。

DPO：跳过显式 RL

在「最优策略与 RM 一一对应」的假设下，RM + KL 约束 PPO 可以消掉 r_φ，变成对偏好对的分类损失：

L = −log σ( β ( log π(y_w|x)/π_ref(y_w|x)
              − log π(y_l|x)/π_ref(y_l|x) ) )

只需要 policy 和冻结的 ref，只要能算两条回复的 logπ。优点：实现短、稳定。缺点：离线偏好，不会自己采样探索；分布外容易歪；长度偏差（更长的 y 往往 logπ 更低或 RM 更偏）要单独处理。

IPO / KTO / SimPO 改的是「这个 sigmoid 差」的形状或要不要 ref。主干仍是：两条序列的 logπ 对比。

GRPO：组内相对优势

同一个 prompt 采 G 条回复，用组内分数当 baseline，不训 value model：

A_i = (r_i − mean({r_1..r_G})) / std({r_1..r_G})
ratio_i = exp( logπ_θ(y_i) − logπ_old(y_i) )
L = min( ratio·A , clip(ratio, 1−ε, 1+ε)·A ) − β KL

A_i 通常广播到这条回复的每个 completion token 上（token-level 损失、序列级优势）。数学、代码、竞赛这种可验证奖励（对 1 错 0）特别合适：一组里天然有对有错。

几个会改数值、但不改问题本身的旋钮：

  • std 过小（G 条奖励全一样）时 A≈0，这组没梯度。有人改成只减均值、不除 std（Dr.GRPO 一类）。
  • leave-one-out：baseline 用「除自己以外的组内均值」，自己的 r 不进 baseline，偏差更小。
  • 损失平均：按 token 平均还是按序列平均。长回复会被 token-mean 稀释。
内存炸弹来自 G × 序列长度 × 词表。朴素路径要物化每条回复的完整 logits。G=64、V=15 万时，光 logprob 就能把显存打满。这是 fused logp 存在的原因。

一步 GRPO 在框架里怎么走

TRL / OpenRLHF / verl / slime / vime 编排不同，算术相同：

  1. Rollout：推理引擎按 π_old 采样 G 条，记下 token id 和 old_logprob。
  2. Reward：规则、裁判模型或 RM → 每条一个 r_i，组内算 A_i。
  3. 重算 logπ：训练引擎对同一条 y 做 teacher-forcing，得到 logπ_θ。
  4. 损失：masked 的 clip(ratio, A)，加上 KL。只在 completion 位置平均。
  5. 反传 + 同步：梯度更新 policy，权重拷回推理引擎。

Hybrid engine（verl 那套）：推理卡跑 vLLM，训练卡跑 FSDP/Megatron，中间搬权重和 token。两边必须看到同一份 checkpoint、同一套 tokenizer、同一侧 padding，否则第 3 步和第 1 步比的不是同一个量。

必须分清的两个 logprob

名字谁算干什么
old_logprobrollout 引擎（vLLM / sglang）importance ratio 的分母
训练侧重算 logprobMegatron / FSDP / DeepSpeedratio 的分子、梯度入口

同一条 token 序列、同一份权重，两边应对齐。对不齐就会出现假 KL、假 advantage，策略在优化噪声。packing、batch 大小、TP 切分都会改归约顺序——下一页。
