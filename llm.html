LLM 对齐：RLHF、DPO、GRPO

语言模型的 RL：状态是 prompt+已生成 token，动作是下一个 token，奖励往往很稀疏（整段回复才打一分）。

为什么 SFT 不够

SFT 模仿人类示范：max log π(y|x)。它不会说「这个答案比那个好多少」，也不会在没有示范的任务上自己探索。对齐需要一种能比较、能探索的目标，这就是 RL 或 RL 的近亲。

经典三阶段（InstructGPT）

  1. SFT：示范数据。
  2. Reward model：人类在两个回复里选更好的那个，学 r_φ(x,y)。
  3. PPO：策略最大化 r_φ，同时 KL 惩罚别离 SFT 太远。
reward = r_φ(x,y) − β KL(π || π_SFT)

论文：InstructGPT / Ouyang et al. 2022。要配一个 value model 估优势，工程重：四个模型（policy、SFT ref、RM、value）同时在场。

DPO：跳过显式 RL

DPO 把 RM + PPO 收成一个分类损失。输入仍是偏好对 (y_w, y_l)：

L = −log σ( β ( log π(y_w|x)/π_ref(y_w|x)
              − log π(y_l|x)/π_ref(y_l|x) ) )

优点：实现简单、稳定、只要 logprob。缺点：离线偏好，不会自己采样探索；分布外容易歪。

同类还有 IPO、KTO、SimPO。先把 DPO 公式抄熟，再看变体。

GRPO：现在开源 LLM RL 的主流

DeepSeekMath / DeepSeek-R1 用的 Group Relative Policy Optimization。核心变化：

  • 同一个 prompt 采 G 条回复（group）。
  • 优势用组内相对分数，不要 value model。
  • 目标仍是 PPO 风格的 clipped ratio + KL。
A_i = (r_i − mean(r_group)) / std(r_group)
ratio_i = exp( logπ_θ(y_i) − logπ_old(y_i) )

数学、代码、竞赛这种「可验证奖励」（对就 1，错就 0）特别适合 GRPO：组内天然有相对高低。

GRPO 的内存炸弹来自 G × 序列 × 词表 的 logits / logprob。RL-Kernel 的 fused logp、prefix-shared attention 就是冲这个来的。

开源框架（编排层，不是算子层）

  • huggingface/trl — 入门 PPO/DPO/GRPO，API 友好
  • OpenRLHF/OpenRLHF — 生产向 RLHF
  • volcengine/verl — 字节 veRL，hybrid engine
  • THUDM/slime — Megatron + vLLM 的训练栈
  • vllm-project/vime — vLLM 生态的 RL 编排；RL-Kernel 往这里插算子

这些框架管调度、数据、权重同步。RL-Kernel 不管这些，只替换 logprob / KL / packing 这些热路径。
